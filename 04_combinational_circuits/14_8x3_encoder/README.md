## 📖 Overview

An **8-to-3 Binary Encoder** is a combinational circuit that converts **one of eight active input lines** into a compact **3-bit binary code** representing which input is active. In effect, it's the mirror image of the Demultiplexer built in the previous project — where a DEMUX expands one signal into many, an encoder compresses many signals back down into one compact code.

A standard binary encoder assumes **exactly one input is HIGH at a time** — a one-hot input. If more than one input goes active simultaneously, the output becomes ambiguous, since the circuit has no way to decide which active line "wins." That limitation is exactly what motivates the **Priority Encoder**, coming up next in this repository.

## ⚙️ Boolean Expressions

$$B_0 = D_1 + D_3 + D_5 + D_7$$

$$B_1 = D_2 + D_3 + D_6 + D_7$$

$$B_2 = D_4 + D_5 + D_6 + D_7$$

Each output bit is simply the OR of every input index where that bit position is set in the binary encoding — no priority logic, no conditionals, just direct OR combinations straight from the truth table.

---

## 💻 Verilog Implementation

The encoder is implemented using **continuous assignment statements (`assign`)**. Each output bit is generated by OR-ing the input lines that correspond to it in the truth table above — a clean, direct translation from Boolean equation to RTL with no procedural logic required.

---

## 🔥 One-Hot Encoding

The encoder expects its input to be **one-hot** — exactly one input bit HIGH, every other bit LOW.

**Valid one-hot inputs:**

```
00000001
00000010
00000100
00001000
00010000
00100000
01000000
10000000
```

**Invalid inputs:**

```
00000000   ← no input active
00000110   ← two inputs active
10100000   ← two inputs active
```

When more than one input is HIGH at once, a standard encoder has no way to determine which input should be encoded — the output becomes undefined/ambiguous. This exact gap is what a Priority Encoder is built to close.

---

## 🧪 Simulation

The testbench applies every valid one-hot input and verifies the generated binary output matches the expected input index. For example:

```
Input  = 00001000
Output = 011
```

`011` = 3, correctly identifying that **D3** is the active input.
